## 프로젝트 소개

**남양주 스마트주정차**는 남양주시의 스마트주정차 단속 데이터를 관리·조회·통계분석하기 위한 Windows 전용 데스크톱 애플리케이션입니다.

- Electron 기반 — 별도의 서버·인터넷 연결 없이 로컬에서 완전히 동작
- SQLite 내장 데이터베이스로 단속 기록 및 CCTV 정보를 안전하게 저장
- 설치 시 관리자 권한 불필요 (사용자 AppData에 설치)
- 자동 업데이트 — 앱 실행 시 GitHub Releases에서 최신 버전 자동 감지 및 설치

## 단속 데이터 분석 기법 해설

> 이 섹션은 v1.1.0에서 도입된 분석 도구의 동작 원리를 제3자도 검증할 수 있도록 상세히 기술합니다.

### 분석 대상 데이터

분석 도구는 사용자가 **지도 탭에 직접 업로드한 파일의 마커**만을 대상으로 합니다.  
데이터베이스(enforcement 테이블) 전체와는 완전히 독립적으로 동작합니다.

각 마커는 최소한 다음 정보를 포함합니다:

| 필드 | 예시 | 용도 |
|------|------|------|
| GPS 위도 (`gps_x`) | 37.6523 | 공간 위치 특정 |
| GPS 경도 (`gps_y`) | 127.2134 | 공간 위치 특정 |
| 단속일시 | 2024-04-12 14:09 | 시간 분석 |
| 단속장소 | 다산중앙로 82번길 | 위치 명칭 표시 |

분석 파이프라인은 아래 3단계로 구성됩니다.

```
[원시 마커 좌표]
      │
      ▼ Step 1. 200m 격자 사전 집계
[격자별 건수 집계]
      │
      ▼ Step 2. DBSCAN 클러스터링
[자연스러운 군집 병합]
      │
      ▼ Step 3. Z-score + 추세 이상감지
[이상 구간 자동 태그]
```

---

### Step 1 — 200m 격자 사전 집계

#### 왜 격자를 먼저 만드나요?

마커가 수천 개일 때 개별 좌표를 그대로 DBSCAN에 넣으면 계산량이 **마커수²** 에 비례하여 매우 느려집니다.  
격자로 먼저 묶으면 수천 개의 마커가 수백 개의 격자 중심점으로 압축되어, 이후 단계가 훨씬 빠르게 동작합니다.

#### 격자 크기 산정

위도 1도 ≈ 111km, 경도 1도 ≈ 88km (위도 37° 기준) 이므로:

```
격자 단위(위도) = 200m ÷ 111,000m/° ≈ 0.0018°
격자 단위(경도) = 200m ÷  88,000m/° ≈ 0.00227°
```

각 마커의 GPS 좌표를 격자 인덱스로 변환합니다:

```
격자_위도_인덱스 = round(위도 / 0.0018)
격자_경도_인덱스 = round(경도 / 0.00227)
```

같은 인덱스를 가진 마커들은 동일한 **약 200m × 200m 격자 셀** 안에 있는 것으로 간주하고 합산합니다.

#### 격자 집계 결과 예시

| 격자 인덱스 | 중심 위도 | 중심 경도 | 총 건수 | 최근 3개월 | 최근 12개월 |
|------------|---------|---------|--------|----------|-----------|
| (20924, 56065) | 37.6632 | 127.2227 | 4,395 | 312 | 1,847 |
| (20921, 56061) | 37.6577 | 127.2136 | 2,108 | 198 | 943 |

> **한계**: 격자 경계선에 걸쳐 있는 핫스팟은 두 셀로 쪼개져 각각 과소평가될 수 있습니다.  
> Step 2의 DBSCAN이 이 문제를 해결합니다.

---

### Step 2 — DBSCAN 공간 클러스터링

#### DBSCAN이란?

DBSCAN(Density-Based Spatial Clustering of Applications with Noise)은 **밀도 기반 군집화 알고리즘**입니다.  
미리 군집 수를 정하지 않아도 되고, 이상치(노이즈)를 자동으로 걸러낼 수 있습니다.

> 쉽게 말하면: "서로 가까운 점들은 같은 핫스팟으로 묶어준다"

#### 핵심 파라미터

| 파라미터 | 설정값 | 의미 |
|---------|--------|------|
| **eps** (반경) | 250m | 이 거리 이내의 격자 중심점은 같은 군집으로 병합 |
| **minPts** | 1 | 단독 격자도 군집으로 유지 (필터링 목적이 아닌 병합 목적) |

#### 거리 계산 — Haversine 공식

격자 중심점 간 거리는 위경도 좌표계에서 **Haversine 공식**으로 계산합니다.  
이는 지구의 곡률을 반영한 실제 지표면 거리이며, 단순 유클리드 거리(피타고라스)보다 정확합니다.

```
a = sin²(Δlat/2) + cos(lat₁) × cos(lat₂) × sin²(Δlng/2)
거리 = 2R × arctan2(√a, √(1−a))      [R = 지구 반경 6,371,000m]
```

#### DBSCAN 동작 순서

```
1. 모든 격자 셀을 "미방문" 상태로 초기화
2. 각 격자 셀에 대해:
   a. 반경 250m 이내의 이웃 격자 목록 조회
   b. 이웃이 1개 이상이면 → 같은 군집 ID 부여
   c. 이미 군집에 속한 셀은 건너뜀
3. 같은 군집 ID를 가진 셀들을 하나의 핫스팟으로 병합
```

#### 병합 후 통계 재계산

```
병합_총건수    = 군집 내 모든 격자 건수의 합
병합_중심_위도 = Σ(격자_위도 × 격자_건수) ÷ 병합_총건수   ← 건수 가중 평균
병합_중심_경도 = Σ(격자_경도 × 격자_건수) ÷ 병합_총건수
월_평균        = 병합_총건수 ÷ 분석_기간(개월 수)
```

#### 격자 방식 vs DBSCAN 비교

```
[격자 방식]                    [DBSCAN 방식]
  ┌───┬───┐                      ┌─────────┐
  │145│132│  ← 경계에서 분리      │   277   │  ← 자연스럽게 병합
  └───┴───┘                      └─────────┘
  같은 도로인데 두 핫스팟         하나의 핫스팟으로 인식
```

> **안전장치**: DBSCAN 처리 중 오류 발생 시 Step 1의 격자 결과로 자동 복귀합니다.

### Step 3 — 위험도 등급 분류

월 평균 건수를 기준으로 4단계 등급을 부여합니다.

| 등급 | 기준 (월 평균) | 색상 | 의미 |
|------|-------------|------|------|
| 🔴 상시단속 | 20건 이상 | 빨강 | 상시적으로 집중 단속이 이루어지는 구간 |
| 🟠 고위험 | 10건 이상 | 주황 | 빈번한 단속이 발생하는 고위험 구간 |
| 🟡 주의 | 3건 이상 | 노랑 | 단속 이력이 있어 주의가 필요한 구간 |
| 🟢 보통 | 3건 미만 | 초록 | 단속 빈도가 낮은 구간 |

> 단, 총 건수가 3건 미만인 격자는 분석 대상에서 제외하여 우연에 의한 오탐을 방지합니다.

### Step 4 — 이상감지 (Z-score + 추세 비율)

#### 4-1. Z-score 이상감지 (횡단면 분석)

Z-score는 "이 핫스팟이 전체 핫스팟 중에서 얼마나 극단적인가"를 수치화합니다.

```
전체_평균(μ) = 모든 핫스팟의 월평균 건수 합 ÷ 핫스팟 개수
표준편차(σ) = √[ Σ(각 핫스팟의 월평균 − μ)² ÷ 개수 ]
Z-score     = (해당 핫스팟의 월평균 − μ) ÷ σ
```

**판정 기준: Z-score > 2.5** → `⚡ 이상` 배지 표시

Z-score 2.5는 통계학에서 **전체의 상위 0.6%** 에 해당하는 값으로,  
정규분포를 가정할 때 이 수준 이상이면 우연으로 발생하기 어려운 이상치로 봅니다.

```
예시:
  평균 월 단속건수 = 15건, 표준편차 = 8건
  어떤 구간의 월 단속건수 = 45건
  Z-score = (45 − 15) ÷ 8 = 3.75  →  ⚡ 이상 표시
```

#### 4-2. 추세 이상감지 (시계열 분석)

최근 3개월의 단속 빈도가 이전 추세 대비 급격히 증가했는지를 탐지합니다.

```
과거_분기_평균 = (최근12개월 건수 − 최근3개월 건수) ÷ 3
                [나머지 9개월을 3분기로 나눈 분기당 평균]

추세_비율 = 최근3개월 건수 ÷ 과거_분기_평균
```

**판정 기준: 추세_비율 > 2.0 이고 최근3개월 건수 ≥ 5건** → `📈 급증` 배지 표시

즉, 최근 3개월의 단속이 **이전 분기 평균의 2배를 초과**하면 급증으로 판정합니다.  
5건 미만인 경우는 표본이 너무 적어 신뢰도가 낮으므로 제외합니다.

```
예시:
  최근 12개월 = 120건, 최근 3개월 = 60건
  과거 분기 평균 = (120 − 60) ÷ 3 = 20건
  추세 비율 = 60 ÷ 20 = 3.0  →  📈 급증 표시
```

> **주의**: 업로드 파일에 날짜 정보(`단속일시`)가 없으면 최근 3개월/12개월 값이 0이 되어  
> 추세 이상감지는 동작하지 않습니다. Z-score 이상감지는 날짜 무관하게 항상 동작합니다.

---

### 분석 결과의 한계와 유의사항

| 항목 | 내용 |
|------|------|
| **표본 편향** | 수동으로 업로드한 파일의 데이터만 분석합니다. 전체 단속 데이터를 반영하지 않을 수 있습니다. |
| **격자 근사 오차** | 200m 격자는 실제 도로 구조를 반영하지 않아, 도로가 격자 경계를 가로지르는 경우 약간의 오차가 발생합니다. |
| **DBSCAN eps 설정** | eps=250m은 남양주시 도로 밀도를 고려한 경험적 설정값입니다. 좁은 골목이 밀집된 지역에서는 별개 핫스팟이 합쳐질 수 있습니다. |
| **월 평균 계산 기준** | 분석 기간은 업로드 파일의 가장 이른 날짜~가장 늦은 날짜로 자동 산정됩니다. 날짜 정보 없는 파일은 1개월로 처리합니다. |
| **Z-score 가정** | Z-score는 데이터가 정규분포에 가깝다고 가정합니다. 단속 건수 분포가 크게 편향된 경우 임계값 2.5의 의미가 달라질 수 있습니다. |

## 알려진 동작 특성

- **동일 버전 재배포 시 자동 업데이트 불가**: 버전 번호가 같으면 electron-updater가 업데이트로 인식하지 않음. 수정 사항이 있으면 반드시 버전을 올려서 배포해야 합니다.
- **asar 비활성화**: better-sqlite3 네이티브 모듈 호환성을 위해 `asar: false` 설정 사용 중.
- **혼재 파일 처리**: 고정형·주행형·시민신고가 하나의 Excel 파일에 섞여 있어도 행(Row) 단위로 유형을 판별하여 각각 처리합니다.
- **어린이보호구역**: 공공데이터포털 API 실시간 호출 — 인터넷 연결이 필요하며, 남양주시(시군구코드 41360) 데이터를 가져옵니다. 좌표는 EPSG:5181(한국 TM) → WGS84로 변환합니다.
- **분석 도구**: DB 단속 데이터가 아닌 지도탭에서 수동 업로드한 마커만 분석합니다. 파일 업로드 후 사용하세요.
